# Лабораторная работа 2

## Состав решения

Проект содержит минимальное Spring Boot-приложение с endpoint `GET /health`.
Исходники находятся в `src/main/java/ru/mipt/healthservice`.

`Dockerfile` реализует multi-stage-сборку:

- builder-этап собирает JAR с помощью Maven;
- runtime-этап использует минимальный JRE Alpine-образ;
- приложение запускается от non-root пользователя `app`;
- настроены `ENV`, `EXPOSE`, `HEALTHCHECK` и exec-form `ENTRYPOINT`;
- базовые образы используют фиксированные версии.

## Многоконтейнерная архитектура

`docker-compose.yml` описывает стек из трёх сервисов:

- `nginx` — reverse proxy с единственным опубликованным портом `80`;
- `app` — Spring Boot-приложение;
- `db` — PostgreSQL `16.4-alpine`.

Сервисы разделены сетями `frontend` и `backend`. Nginx подключён к обеим
сетям, приложение — к обеим сетям, PostgreSQL — только к `backend`.
Порты приложения и базы данных наружу не публикуются.

Данные PostgreSQL хранятся в named volume `pgdata`. Конфигурация окружения
представлена файлом `.env.example`, а реальные значения `.env` исключены из
Git и Docker build context.

## Registry

Скрипт `scripts/build-and-push.sh` выполняет сборку Docker-образа и его
публикацию в указанный registry. Скрипт не содержит учётных данных или
секретов.

## Сборка и запуск

Для запуска требуется локальный файл `.env` на основе `.env.example`.
Файл `.env` содержит параметры PostgreSQL и не коммитится в репозиторий.

Сборка и запуск многоконтейнерного приложения выполняются командой:

```bash
docker compose up -d --build
```

После запуска доступны контейнеры `nginx`, `app` и `db`. Единственная
внешняя точка входа — Nginx на порту `80`.

Проверка состояния стека:

```bash
docker compose ps
```

Проверка приложения через reverse proxy:

```bash
curl -i http://localhost/health
```

Ожидаемый результат — HTTP `200` и JSON-ответ со статусом `UP`.

Для остановки контейнеров без удаления данных PostgreSQL используется:

```bash
docker compose down
```

Named volume `pgdata` сохраняется между остановкой и повторным запуском
стека. Удаление volume выполняется только отдельной командой:

```bash
docker compose down -v
```

## Критерии проверки

Работоспособность решения подтверждается статусом `healthy` для сервисов
`app` и `db`, доступностью приложения через Nginx по endpoint `/health` с
ответом HTTP `200`, отсутствием внешних портов у `app` и `db`, а также
сохранением данных PostgreSQL в volume `pgdata` между перезапусками стека.
